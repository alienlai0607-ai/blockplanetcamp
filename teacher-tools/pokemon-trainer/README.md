## USB 備份中斷恢復（read-fix 3）

使用者在 read-fix 2 實機備份時，於 `0xad0000` 回報封包長度不符。截圖未含實際封包長度，尚不能判定是空 SLIP、資料截短或其他設備回應；不將此問題宣稱為已完成實機修復。

- 一般讀取改為 1024-byte 封包，仍維持最多一包待確認；忽略有數量與時間上限的空 SLIP 封包，非空資料仍嚴格驗證預期長度及 MD5。
- 讀取錯誤可在同一次作業中重連最多 2 次，改用 512-byte 封包。重建連線並進入下載模式後，重新確認晶片、安全狀態、容量、MAC，並以設備 MD5 比對已讀前綴，才從失敗的 64 KiB 區塊繼續；不混用不同設備或重連後改變的資料。
- 完整備份的全區 MD5、SHA-256、瀏覽器保存校驗與下載確認仍保留。寫入失敗不自動重寫；只有讀取及寫入後校驗允許重連。
- ACK 寫入被拒絕時以 `finally` 釋放 Web Streams writer，避免舊連線無法關閉。診斷記錄新增預期／實際封包長度、階段及重連次數，不記錄備份內容。

完整測試 67 項通過，新增真實 vendored Transport／Web Streams 的 16 MiB 模擬資料讀取、空封包、512-byte 備援、ACK 失敗釋放鎖、在 `0xad0000` 中斷後接續，以及設備／前綴變更和重試上限的拒絕測試。韌體二進位檔不變。直接 USB 診斷的提權請求被環境權限政策拒絕，仍待使用者 Chrome／StopWatch 實機確認。

### 前一版修正（read-fix 2）

使用者回報備份約 12% 時出現 `Serial data stream stopped`。已在實際 esptool-js 0.7.1 + Transport + Web Streams 的模擬設備測試中重現：原版 `readFlash()` 讀完資料就返回，未接收 stub 最後的 16-byte MD5；下一個讀取命令可能在 stub 返回命令模式前送出而遺失。

`esp-flash-read.js` 保留原廠套件不變，只替換讀取函式：每包 4096 bytes、最多一包未確認、嚴格檢查長度，並在下一命令前收完及驗證 MD5。USB 接收緩衝設為 64 KiB。完整 16 MB 備份仍另做全區 MD5、SHA-256 和 IndexedDB 讀回校驗；備份失敗不開放寫入。遵循 [Espressif READ_FLASH 通訊規格](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/advanced-topics/serial-protocol.html#reading-flash)。

備份失敗現在會顯示階段及重連方式，並可下載 `StopWatch-USB-diagnostic.txt`（不含備份內容）。連續讀取、延遲校驗封包、截短／錯誤／缺失封包及備份失敗禁止寫入等回歸測試通過；完整測試共 59 項通過。未修改韌體二進位檔，未燒錄設備。這次直接開啟本機 USB 埠被執行環境拒絕，且無可用的瀏覽器控制工具，因此仍須以使用者 Chrome／StopWatch 確認實機結果。

1. 按「背景製造」，選早晨、白天或夜晚。每張背景固定 64 × 64 像素。
2. 直接改畫像素範例，或按垃圾桶清空這個時段，從空白開始。

### 播放相容性修正

原生計時器必須以全域物件呼叫，不能存成播放器方法後直接呼叫。播放與清除計時器都改由全域呼叫包裝；新增會檢查接收者的回歸測試，舊版會重現 Illegal invocation，修正版通過。DOM 測試也驗證不同畫格的實際繪圖資料有切換。只有一格時按播放會提示新增第二格，所有畫格相同時提示修改圖案。

參考：[MDN 計時器的 this 說明](https://developer.mozilla.org/zh-TW/docs/Web/API/Window/setInterval#「this」問題)。仍未取得實機瀏覽器驗證。
